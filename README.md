The client was The Gaming Room and they wanted an application based on the existing game called Draw It or Lose It. The application needed to handle certain aspects such as games, teams and played. Some things to consider were how secure the data was, the amount of memory and storage the application would take up, and the system requirements needed to run the game. 
In developing the software design document, I was able to successfully document the client’s requests and break down aspects of the design into smaller parts that were more manageable. I also discussed the advantages and disadvantages of different operating systems and mobile devices. By effectively explaining the memory and storage aspects I was able to acknowledge what the application needed to efficiently manage data and system resources. 
The design process document was helpful as it provided a blueprint that can be followed when writing code. The UML class diagram was useful in knowing what classes would be needed when coding and what information each class would contain. 
One thing I would revise would be adding more detail on the security aspect of the application and how it will be used for each operating platform. I would add a section in the Development Requirements to include security standards that could be implemented for each platform. 
In order to interpret the users’ needs and implement them into the software design I focused on what the program should accomplish and the features were necessary. This is important as it satisfies the requirements while avoiding unnecessary attributes. The program may still work but if the client’s requests are not satisfied the project is not successful. 
To design the program, I took the approach of looking at the project from both the user and programmers’ perspective. By doing this I am able to see how the user will interact with the program and how I can design a system on the backend that considered memory, security and functionality. In the future some techniques I would use to design a similar application would be to interview the client, utilizing UML class diagrams and providing the client with a summary of what they are requesting and how it will be accomplished.
